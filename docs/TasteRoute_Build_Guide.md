## 0. 작업 방식

### 한 단계를 도는 순서

```
① 개념·수식 이해 → ② 직접 구현 → ③ 코드 리뷰
→ ④ 확인 명령 실행, 정답지 숫자와 비교 → ⑤ 커밋
```

- 정답지는 제안서 9장의 예비 결과입니다. 같은 수식을 따로 구현하므로 소수점까지 같지는 않습니다. 지표마다 허용 오차를 따로 둡니다.

  | 지표 | 통과 범위 |
  | --- | --- |
  | RMSE, MAE | 정답 ±0.005 |
  | P@K, Recall@K, NDCG@K | 정답의 ±20% (값이 0.001~0.03이라 절대 오차 0.005는 너무 느슨함) |
  | 평균 거리 | 정답 ±0.2km |
  | 경로 길이 비율, 최적해 비율 | 정답 ±2%p |
  | 실행 시간 | 같은 자릿수 (기계마다 다름) |
- 한 단계를 통과하기 전에 다음 단계로 넘어가지 않습니다. 뒤 단계가 앞 단계 위에 쌓이기 때문입니다 (MF, kNN, CBF는 모두 bias 모델 위에 쌓임).

### 데이터에서 미리 확인한 사실 (2026-10-24)

구현할 때 그대로 전제로 써도 되는 값입니다.

| 항목 | 값 | 구현에 주는 의미 |
| --- | --- | --- |

### 모든 모델의 공통 인터페이스

```python
class 모델:
    def fit(self, train_df): ...             # 학습. train_df는 u, i, stars 열을 가짐
    def predict(self, u, i) -> np.ndarray:   # u, i는 같은 길이의 정수 배열. 예측 별점 배열 반환
    def score_all(self, u) -> np.ndarray:    # 사용자 u 한 명의 전체 가게(7,693개) 예측 별점
```

- `predict`는 **배열을 한 번에** 받습니다. 평점 7만 개를 for문으로 한 개씩 예측하면 느립니다.
- 예측값은 마지막에 `np.clip(pred, 1, 5)`로 1~5 사이로 자릅니다.
- 이렇게 맞추면 평가, Hybrid, 재순위화 코드가 어느 모델이든 똑같이 돌아갑니다.

### 공통 numpy 기법: 그룹 합은 `np.bincount`

이 프로젝트에서 가장 많이 쓰는 기법입니다. "사용자별 합", "가게별 개수"를 pandas groupby 대신 빠르게 구합니다.

```python
np.bincount(u, weights=값, minlength=사용자수)   # 사용자별 값의 합
np.bincount(u, minlength=사용자수)               # 사용자별 개수
```

`minlength`를 꼭 넣어야 배열 길이가 전체 사용자 수와 맞습니다 (번호가 큰 사용자가 train에 없을 때 길이가 짧아지는 것을 막음).

### A2. `src/tasteroute/metrics.py` — 오차 지표

**목표:** RMSE, MAE (랭킹 지표는 B1에서 추가).

$$\text{RMSE} = \sqrt{\frac{1}{|T|}\sum_{(u,i)\in T}(r_{ui}-\hat r_{ui})^2} \qquad \text{MAE} = \frac{1}{|T|}\sum |r_{ui}-\hat r_{ui}|$$

**구현 방법:** numpy 배열 두 개를 받아 한 줄씩. 

**통과 기준:** `rmse([1,2,3],[1,2,5]) == sqrt(4/3) ≈ 1.1547`, `mae([1,2,3],[1,2,5]) ≈ 0.6667`

**덤:** `evaluate(model, df)` 함수를 하나 두면 편합니다. `model.predict(df.u.values, df.i.values)`로 예측해 RMSE, MAE를 dict로 돌려줍니다. 이후 모든 단계에서 재사용합니다.

### A3. `src/tasteroute/models/baseline.py` — 전체 평균, Bias 모델 ★ 가장 중요

**목표:** 가장 단순한 기준선 두 개. 뒤의 모든 모델이 bias 위에 쌓입니다.

**개념**
- 전체 평균: 누구에게나 μ(train 평균 별점)를 예측.
- Bias: "이 사용자는 원래 짜게 준다(b_u < 0)", "이 가게는 원래 잘 받는다(b_i > 0)"를 반영.

$$\hat r_{ui} = \mu + b_u + b_i$$

손실 (L2 정규화로 평점이 적은 사용자·가게의 bias를 0 쪽으로 당김):

$$\min_{b}\sum_{(u,i)}(r_{ui}-\mu-b_u-b_i)^2 + \lambda\Big(\sum_u b_u^2+\sum_i b_i^2\Big)$$

**교대 갱신 (닫힌 해):** b_u를 고정하면 b_i의 최적값이 바로 계산되고, 반대도 마찬가지입니다. 번갈아 10번 반복합니다.

$$b_i = \frac{\sum_{u \in U_i}(r_{ui}-\mu-b_u)}{\lambda + |U_i|} \qquad b_u = \frac{\sum_{i \in I_u}(r_{ui}-\mu-b_i)}{\lambda + |I_u|}$$

**구현 방법**
- 분자는 `np.bincount(i, weights=잔차, minlength=가게수)`, 분모의 개수는 `np.bincount(i, minlength=가게수)`.
- 배열 크기는 train에 나온 최대 번호가 아니라 **전체 사용자 수(31,743), 전체 가게 수(7,693)**로 잡습니다. 그래야 train에 없는 가게 3곳의 bias가 자동으로 0이 됩니다 (분자 0 / 분모 λ).
- `score_all(u)` = `μ + b_u[u] + b_i` (b_i 전체 배열). 한 줄입니다.

**튜닝:** λ ∈ {1, 5, 10, 25}에서 **warm val RMSE**가 가장 낮은 값을 고릅니다. test는 마지막에 한 번만 봅니다.

**통과 기준**

| 모델 | warm val RMSE | warm test RMSE |
| --- | --- | --- |
| 전체 평균 | - | 1.190 |
| Bias, λ=5 (최적) | 1.043 근처 | 1.051 |

λ별 val 곡선이 1에서 5로 내려갔다가 25로 다시 오르는 U자 모양이면 정상입니다 (1.054 → 1.044 → 1.050 → 1.070).

**자주 틀리는 곳**
- μ를 val/test까지 포함해 계산 → 데이터 누수. **train 평균만** 씁니다.
- b_u와 b_i를 동시에 계산 → 교대가 아닙니다. 하나를 갱신한 **새 값**으로 다른 하나를 계산합니다.

### A4. `src/tasteroute/models/mf.py` — Matrix Factorization (SGD)

**목표:** 사용자·가게마다 f차원 잠재 벡터를 학습.

$$\hat r_{ui} = \mu + b_u + b_i + p_u^\top q_i$$

$$\min \sum_{(u,i)}(r_{ui}-\hat r_{ui})^2 + \lambda\big(b_u^2+b_i^2+\|p_u\|^2+\|q_i\|^2\big)$$

**SGD 갱신 (평점 한 개마다):** $e_{ui} = r_{ui}-\hat r_{ui}$

$$b_u \leftarrow b_u+\eta(e_{ui}-\lambda b_u) \qquad b_i \leftarrow b_i+\eta(e_{ui}-\lambda b_i)$$
$$p_u \leftarrow p_u+\eta(e_{ui}q_i-\lambda p_u) \qquad q_i \leftarrow q_i+\eta(e_{ui}p_u-\lambda q_i)$$

**구현 방법**
- 초기값: `P = rng.normal(0, 0.1, (사용자수, f))`, `Q`도 같게. b는 0. `rng = np.random.default_rng(42)`로 seed 고정.
- 매 epoch 시작 시 평점 순서를 섞습니다 (`rng.permutation`).
- p_u와 q_i는 **갱신 전 값**으로 서로를 갱신합니다. `pu = P[u].copy()`를 먼저 저장하세요.
- 조기 종료: 매 epoch 끝에 val RMSE를 재고, **3 epoch 연속 개선이 없으면** 멈추고 가장 좋았던 시점의 파라미터로 돌아갑니다.
- epoch마다 train/val RMSE를 리스트에 기록 → 그림 M3(학습 곡선).

**속도:** 순수 파이썬 for문으로 31만 개를 돌면 epoch당 수 초입니다. 16개 설정 × 약 20 epoch이면 몇 분이라 괜찮습니다. 너무 느리면 `numba`의 `@njit`를 붙이면 수십 배 빨라집니다 (선택, 쓰면 수업 외 라이브러리로 설명 필요).

**튜닝:** f ∈ {10, 20, 50, 100} × λ ∈ {0.01, 0.02, 0.05, 0.1}, η = 0.01 고정 (16개). 결과를 표로 저장 → 그림 M4(히트맵).

**통과 기준:** f=10, λ=0.1에서 val 1.044, test 1.052 근처. 약 15 epoch에서 멈춤.

**해석 포인트 (발표용):** MF가 bias를 못 이깁니다. 사용자당 학습 평점 중앙값이 6개라 잠재 요인을 배울 신호가 부족하고, 그래서 f가 가장 작고 λ가 가장 큰 설정이 이깁니다. 이것 자체가 보고할 결과입니다.

**자주 틀리는 곳**
- 학습률이 너무 크면 RMSE가 발산(nan). η=0.01에서 시작.
- val로 조기 종료하고 그 val 점수를 최종 성능으로 보고 → 최종 성능은 test로.

### A5. `src/tasteroute/models/item_knn.py` — Item-based kNN

**목표:** "이 사용자가 평가한 가게 중 가게 i와 비슷한 곳들의 평점"으로 예측.

**유사도 3종** (공통 평가자 $U_{ij}$ 위에서)

| 이름 | 중심화 | 의미 |
| --- | --- | --- |
| cosine | 없음 | 원래 별점 그대로 |
| adjusted cosine | 사용자 평균을 뺌 | 짜게 주는 사람 보정 |
| Pearson | 가게 평균을 뺌 | 가게 평균 보정 |

$$s_{ij} = \frac{\sum_{u\in U_{ij}} x_{ui}x_{uj}}{\sqrt{\sum_{u\in U_{ij}} x_{ui}^2}\sqrt{\sum_{u\in U_{ij}} x_{uj}^2}}$$

**Shrinkage:** 공통 평가자가 2명뿐인 유사도는 믿기 어려우므로 0 쪽으로 줄입니다.

$$s'_{ij} = \frac{n_{ij}}{n_{ij}+\beta}\,s_{ij}$$

**예측** (bias 위에 쌓음, $N_k(i;u)$ = u가 평가한 가게 중 i와 가장 비슷한 k개):

$$\hat r_{ui} = b_{ui} + \frac{\sum_{j\in N_k(i;u)} s'_{ij}(r_{uj}-b_{uj})}{\sum_{j\in N_k(i;u)}|s'_{ij}|}$$

이웃이 하나도 없거나, 뽑힌 이웃의 $|s'_{ij}|$ 합이 0이면(분모 0) $b_{ui}$(A3의 bias 예측)로 대체합니다.

**구현 방법 (행렬로 한 번에)**
1. train으로 가게×사용자 희소 행렬 X를 만듭니다 (`scipy.sparse.csr_matrix`). 유사도 종류에 따라 값을 중심화합니다.
2. 내적: `X @ X.T` → 7,693×7,693.
3. **분모는 전체 벡터로 정합니다:** 위 공식은 분모를 "공통 평가자" $U_{ij}$ 위에서만 구하지만, 이 프로젝트는 **각 가게의 전체 평점 벡터 길이**(일반 cosine 정규화)로 나눕니다. 희소 행렬 곱 한 번으로 끝나기 때문입니다. 아래 통과 기준(val 1.140)도 이 정의 기준입니다. 공통 평가자 정규화는 값을 바꾸므로 하려면 별도 실험으로 기록합니다. 어느 정의인지 docstring에 적으세요.
4. 공통 평가자 수: 값이 1인 이진 행렬 B로 `B @ B.T` → $n_{ij}$.
5. 밀집 행렬로 바꾸면 7,693² × 4바이트 ≈ **237MB**가 두 개입니다. `float32`로 저장하고 다 쓰면 `del`합니다.
6. 예측: (u, i) 쌍마다 u가 평가한 가게들의 유사도 `S[i, I_u]`에서 상위 k개를 `np.argpartition`으로 뽑습니다. 사용자별 평가 목록은 미리 dict로 만들어 둡니다.
   - 평점이 k개보다 적은 사용자(중앙값 6개인데 k = 80)는 `k_eff = min(k, |I_u|)`로 줄이거나 argpartition 없이 전부 씁니다 (그대로 넘기면 `kth out of bounds`).
   - $I_u$가 비면 bias 예측을 씁니다. 예측 대상 가게 자신은 이웃에서 뺍니다.

**튜닝:** 유사도 3종 × k ∈ {10, 20, 40, 80}, β = 25 고정 (12개). 여유가 있으면 β ∈ {0, 25, 100}도 → 그림 M1.

**통과 기준:** cosine, k=80에서 val 1.140 근처. **bias(1.04)보다 나쁜 게 정상**입니다. 사용자 평점이 6개뿐이라 이웃 후보 자체가 적기 때문이고, 이것도 보고할 결과입니다.

**참고:** `score_all`은 7,693개 전부 이웃을 찾아야 해서 느립니다. 제안서도 kNN은 랭킹 평가에서 뺐습니다("not ranked"). 구현은 하되 랭킹 실험에서는 제외해도 됩니다.

### A6. `src/tasteroute/models/cbf.py` — Content-based (ridge)

**목표:** 가게 카테고리로 사용자 취향을 학습. 평점이 적은 사용자를 돕는 것이 목적 (RQ2).

**개념:** bias가 못 맞힌 나머지(잔차)를 카테고리로 설명합니다. "이 사용자는 평균보다 에티오피아 음식에 +0.8점 더 준다".

$$y_{ui} = r_{ui} - b_{ui} \qquad \hat r_{ui} = b_{ui} + x_i^\top\theta_u$$

**사용자별 ridge 회귀 (닫힌 해):** $X_u$ = u가 평가한 가게들의 TF-IDF 행 (n_u × 188)

$$\theta_u = (X_u^\top X_u + \lambda_c I)^{-1}X_u^\top y_u$$

**구현 방법**
- 사용자 31,743명 각각 188×188 연립방정식을 풉니다. `np.linalg.solve`를 쓰고, 역행렬(`inv`)은 쓰지 않습니다 (느리고 수치적으로 불안정).
- 사용자 평점이 6개면 $X_u$는 6×188이라 작습니다. 희소 행렬에서 해당 행만 꺼내 `.toarray()`.
- 제안서의 실패 기록: 처음에 잔차를 bias가 아니라 **사용자 평균**으로 만들었더니, 평점 1개인 사용자는 평균이 곧 그 평점이라 잔차가 0이 되고 RMSE가 1.50까지 나빠졌습니다. **반드시 bias 기준 잔차**를 씁니다.

**튜닝:** λc ∈ {0.3, 1, 3, 10, 30}.

**통과 기준:** λc=30에서 val 1.043 근처.

**해석 포인트:** λc=30이 최적이면 θ가 거의 0, 즉 카테고리 항이 거의 꺼진 상태입니다. 카테고리만으로는 정보가 부족하다는 뜻이고, D단계의 특징 보강(가격대, 영업시간)이 개선 후보입니다.

### A7. `src/tasteroute/models/hybrid.py` — Hybrid

**고정 α**

$$\hat r_{ui} = \alpha\,\hat r^{CF}_{ui} + (1-\alpha)\,\hat r^{CBF}_{ui}$$

**적응형 α:** 평점이 많은 사용자일수록 CF를 더 믿습니다. κ = CF와 CBF의 가중치가 같아지는 평점 수.

$$\alpha(n_u) = \frac{n_u}{n_u+\kappa}$$

예: 평점 45개, κ=100이면 α = 45/145 = 0.31.

**구현 방법**
- 이미 학습된 CF 모델(MF)과 CBF 모델을 **받아서** 섞기만 합니다. 다시 학습하지 않습니다.
- $n_u$는 train 평점 수 (`np.bincount`).

**튜닝:** α ∈ {0, 0.1, …, 1} (11개) → 그림 M5. κ ∈ {0.5, …, 100} (9개) → 그림 M6.

**통과 기준:** 적응형 κ=100에서 val 1.043 근처. α 곡선은 거의 평평합니다 (차이 0.0014). 두 모델이 이미 비슷한 예측을 하기 때문입니다.

### A8. `experiments/compare_models.py` — 모델 비교와 cold-start

**목표:** A3~A7을 한 번에 돌려 결과 파일로 저장.

**구현 방법**
1. 각 모델을 val로 튜닝한 최적 설정으로 학습.
2. warm test에서 RMSE, MAE 계산 → `results/model_compare.json` (그림 V1).
3. **신뢰구간 (bootstrap):** 사용자 단위로 1,000번 복원 추출해 RMSE를 다시 계산하고, 2.5%~97.5% 분위수를 구간으로 씁니다. 평점 단위가 아니라 **사용자 단위**로 뽑는 게 포인트입니다.
4. cold-start: m=1, 3, 5 그룹별로 `split=="test"` 이면서 `cold_m==m`인 평점에서 RMSE (그림 V5). 비교 대상은 bias, CF, CBF, Hybrid.

**통과 기준:** Bias, MF, CBF, Hybrid가 1.051~1.052로 거의 같고, kNN 1.142, 전체 평균(Global mean) 1.190. Bias를 제외한 5개 모델이 bias 대비 paired t-test p값을 기록한다 (Bias 자신은 비교 대상이 아니라 없음).

## Part B. 랭킹과 거리 재순위화 (RQ1)

### B1. `metrics.py`에 랭킹 지표 추가

**정의:** $L_u^K$ = 사용자 u에게 추천한 상위 K개, $Rel_u$ = u의 test 평점 중 **별점 4 이상**인 가게.

> $Rel_u$에는 후보 필터(B2: 영업 중, train 평점 20개 이상)에서 빠지는 가게도 들어갑니다. 그래서 어떤 방법도 그 가게를 맞힐 수 없어 Recall@K와 NDCG@K의 절대값은 보수적으로(낮게) 나옵니다. 모든 방법이 같은 정의를 쓰므로 방법끼리의 비교에는 영향이 없습니다. "사용자가 실제로 간 좋은 곳을 얼마나 찾았나"를 그대로 재려고 이 정의를 유지합니다.

| 지표 | 식 | 뜻 |
| --- | --- | --- |
| Precision@K | $\lvert L\cap Rel\rvert / K$ | 추천한 것 중 맞은 비율 |
| Recall@K | $\lvert L\cap Rel\rvert / \lvert Rel\rvert$ | 맞혀야 할 것 중 찾은 비율 |
| HitRate@K | $\lvert L\cap Rel\rvert > 0$이면 1 | 하나라도 맞혔나 |
| NDCG@K | $\frac{\sum_{k=1}^{K} rel_k/\log_2(k+1)}{\text{IDCG}}$ | 맞힌 것이 위쪽일수록 높은 점수 |

IDCG는 관련 있는 가게를 전부 맨 위에 놓았을 때의 DCG입니다 (최대 K개).

**평가 대상:** test에 관련 가게가 1개 이상인 사용자만 넣고, 사용자별 점수를 평균합니다.

**통과 기준:** 손 계산 예제. 추천 [a, b, c], 관련 {b} → P@3 = 1/3, R@3 = 1, NDCG@3 = (1/log₂3) / 1 ≈ 0.631.

### B2. `src/tasteroute/candidates.py` — 후보 생성 (기본형)

**목표:** 사용자마다 추천 후보 50곳을 뽑기.

**제외할 것**
1. 이미 train·val에서 평가한 가게 (이미 간 곳을 추천하면 안 됨)
2. 폐업한 가게 (`is_open == 0`)
3. train 평점 20개 미만인 가게 → 3,288곳만 남음. 평점이 적은 가게는 예측 별점이 들쭉날쭉해서 상위로 튀어 오르는 문제가 있습니다 (제안서 9.1).

**구현 방법:** `score_all(u)`로 전체 점수를 받은 뒤, 제외할 가게 점수를 `-np.inf`로 바꾸고 `np.argpartition`으로 상위 50개를 뽑아 정렬합니다.

**인기순 기준선:** 점수 = train 평점 수. 모델 없이 같은 함수로 돌립니다.

**평가 표본:** 시간을 줄이려고 test 사용자 3,000명을 `seed=42`로 뽑아 고정합니다.

**통과 기준:** 인기순 P@10 ≈ 0.0095, 예측 모델들 0.0005~0.0007. **모델이 인기순에 지는 게 현재 정답**입니다 (D1에서 개선).

### B3. `src/tasteroute/geo.py` — 거리와 기준점

**Haversine** (지구 반지름 R = 6,371km, 위경도는 라디안으로 변환):

$$d = 2R\arcsin\sqrt{\sin^2\frac{\Delta\phi}{2}+\cos\phi_1\cos\phi_2\sin^2\frac{\Delta\lambda}{2}}$$

**만들 함수**
- `haversine(lat1, lon1, lat2, lon2)`: numpy 브로드캐스팅으로 배열끼리 한 번에 계산.
- `distance_matrix(lats, lons)`: N×N 거리 행렬 (동선용).
- `user_anchor(train_df, items)`: 사용자별 기준점 = 그 사용자가 train에서 평가한 가게 위경도의 **중앙값**. 평균이 아니라 중앙값을 쓰는 이유는 멀리 한 번 다녀온 곳에 끌려가지 않게 하려는 것입니다.

**통과 기준:** 같은 점 → 0km. 필라델피아 시청(39.9526, -75.1636) ↔ 뉴욕 타임스스퀘어(40.7580, -73.9855) ≈ 134km.

### B4. `src/tasteroute/rerank.py` — 거리 감쇠 재순위화

**점수:** 예측 별점을 0~1로 바꾼 뒤 거리 가중치를 곱합니다.

$$s_{ui} = \frac{\hat r_{ui}-1}{4}\cdot w(d_{ui})$$

**감쇠 함수 4종** (τ = 거리 척도)

| 이름 | w(d) | 특징 |
| --- | --- | --- |
| 지수 (기본) | $e^{-d/\tau}$ | τ·ln2 ≈ 1.4km마다 점수 절반 (τ=2km) |
| 가우시안 | $e^{-d^2/(2\tau^2)}$ | 가까운 곳은 거의 안 깎고 멀어지면 급격히 |
| 거듭제곱 | $1/(1+d/\tau)$ | 꼬리가 길어 먼 곳도 조금 남음 |
| 컷오프 | $d\le\tau$이면 1, 아니면 0 | 반경 밖은 아예 제외 |

**구현 방법**
- B2의 후보 50곳에 대해 기준점에서의 거리 → 가중치 → 점수 → 다시 정렬 → 상위 K.
- τ를 0.5km~1,000km 사이 10개 정도로 바꿔 가며 (NDCG@10, 목록 평균 거리) 점을 찍으면 그림 R2(정확도 대 거리)가 됩니다. **이 그림이 RQ1의 핵심**입니다.

**통과 기준:** 지수 감쇠 τ=2km에서 NDCG@10 0.0017 → 0.0059 (3.5배), 목록 평균 거리 6.3km → 2.1km. τ를 100km 이상으로 키우면 원래 별점 순서로 돌아가야 합니다.

**해석 포인트:** 가설은 "거리를 넣으면 정확도가 떨어진다"였지만 오히려 올랐습니다. 사람들이 실제로 가까운 곳을 다니고 리뷰하기 때문에 거리 자체가 강한 신호라는 뜻입니다 (그림 E8: 사용자 활동 반경 중앙값 약 2km, 가게 간 거리 중앙값 약 9km).

## Part C. 동선 (RQ3)

### C1. `src/tasteroute/route.py`

**문제:** 출발점(노드 0, 사용자 기준점)에서 시작해 N곳을 한 번씩 모두 들르고 마지막 가게에서 끝나는 가장 짧은 순서 (돌아오지 않는 열린 경로).

**만들 함수 4개** (입력: (N+1)×(N+1) 거리 행렬, 출력: 방문 순서와 총 거리)

| 함수 | 방법 | 복잡도 |
| --- | --- | --- |
| `brute_force` | `itertools.permutations`로 모든 순서 | O(N!) — N=8이면 40,320개 |
| `held_karp` | 비트마스크 DP | O(N²·2ᴺ) — N=8이면 16,384 단계 |
| `nearest_neighbor` | 항상 가장 가까운 미방문 가게로 | O(N²) |
| `two_opt` | 경로의 구간 [a+1, b]를 뒤집어서 짧아지면 채택, 개선이 없을 때까지 | 반복 |

**Held-Karp 구현 방법**
- 상태: `C[S][j]` = 0에서 출발해 집합 S를 정확히 방문하고 j에서 끝나는 최단 거리. S는 정수 비트마스크 (가게 k 방문 = k번째 비트 1).
- 초기: `C[{j}][j] = D[0][j]`.
- 점화식: $C(S,j) = \min_{k\in S\setminus\{j\}} C(S\setminus\{j\}, k) + D_{kj}$
- 답: 모든 j에 대해 `C[전체][j]`의 최솟값. 경로 복원을 위해 `parent[S][j] = 최적 k`를 저장하고 끝에서부터 거꾸로 따라갑니다.
- 배열 크기는 `2^N × N`. N=8이면 256×8로 작습니다.

**2-opt 주의:** 열린 경로라 출발점(노드 0)은 고정입니다. 뒤집는 구간에 0이 들어가면 안 됩니다.

**통과 기준**
- 무작위 거리 행렬 100개(N=3~8)에서 `brute_force`와 `held_karp`의 총 거리가 같음 (C2의 테스트).
- Held-Karp N=8에서 약 2ms, N=10에서 10ms 이하.
- 사용자 3,000명(N=6)에서 NN+2-opt가 약 82%에서 최적과 같음. 추천 순서 그대로 돌면 최적보다 중앙값 27% 김.
