# TasteRoute 발표(PPT) 개요서

작성일: 2026-10-22 · 저장소: https://github.com/leten02/TasteRoute

7분 발표 + Q&A 3분의 슬라이드 구성, 장별 내용과 그림, 시간 배분, 예상 질문을 정리합니다.
그림 ID(E, P, M, R, T, V, X)는 제안서의 그림 번호입니다. 코드 구현 계획은 별도 문서 [TasteRoute_Code_Plan.md](TasteRoute_Code_Plan.md)에 있습니다.

## 1. 발표에 쓸 핵심 결과 (예비)

최종 실험 후 숫자가 바뀌면 이 목록과 슬라이드를 함께 고칩니다.

- 별점 예측: Bias, MF, CBF, Hybrid 모두 test RMSE 약 1.05. Item-kNN 1.14, 전체 평균 1.19
- 랭킹: 인기순 P@10 0.0095가 모든 예측 모델(0.0005~0.0007)보다 높음 → 가장 큰 약점
- 거리 재순위화: tau = 2km에서 NDCG@10 3.5배 상승, 목록 평균 거리 6.3km → 2.1km
- 동선: NN + 2-opt가 82% 사용자에게서 최적해, 추천 순서 그대로 돌면 최적보다 중앙값 27% 더 김

## 2. 발표 개요

- 형식: 팀당 7분 발표 + Q&A 3분
- 과제에서 요구하는 순서: 비즈니스 목적 → 데이터 탐색 → 전처리 → 모델링 → 평가·분석 → 배운 점 → 팀워크 → 오픈소스 SW 구조와 GitHub URL
- 핵심 메시지: "평점만 보는 추천은 멀리 있는 곳을 고른다. 거리를 넣으면 가까워질 뿐 아니라 오히려 더 잘 맞춘다. 그리고 그 장소들을 가장 짧게 도는 경로까지 만든다."
- 분량: 본문 12장 + 부록 4장. 1장당 평균 30~35초

### 3.1 슬라이드 작성 규칙

- 슬라이드 제목은 주제가 아니라 결론으로 씁니다 (예: "결과" 대신 "거리를 넣으니 정확도도 올랐다").
- 한 장에 그림은 최대 2개, 숫자는 핵심 3개 이내로 둡니다.
- 그림은 제안서의 그림을 그대로 씁니다. 최종 실험 후 숫자가 바뀌면 `results/`에서 다시 그립니다.
- 실패한 결과(랭킹 약점, CBF cold-start)도 원인과 대응을 함께 보여 줍니다. 과제가 "성공이든 실패든 결과를 설명"하라고 요구합니다.

### 3.2 Q&A 예상 질문

| 질문 | 답변 요지 | 근거 |
| --- | --- | --- |
| 왜 직선 거리인가 | 도로 거리는 외부 API가 필요해서 범위 밖. 도시 안에서는 순서 비교에 충분하고, 한계로 명시 | 제안서 6.1 |
| 사용자 위치는 어떻게 아나 | Yelp에 위치가 없어서 사용자가 리뷰한 장소 좌표의 중앙값을 사용. 데모는 숙소(호텔 업체) 좌표 | 제안서 6.2 |
| MF가 bias보다 나아지지 않는 이유 | 사용자당 평점이 적어(작업 데이터 중앙값 8개, 학습용 6개) 잠재 요인을 배울 신호가 부족. f가 작을수록 좋았음 | M4 |
| 인기순이 더 잘 맞히면 모델이 왜 필요한가 | 인기순은 모두에게 같은 목록(coverage 0.3%). 개인화와 거리 반영을 위해 후보 생성 단계에 인기도를 섞음 | V3, 구현 목록 4 |
| 거리를 넣었는데 정확도가 왜 오르나 | 사용자가 실제로 가까운 곳을 방문·리뷰하기 때문에 거리 자체가 강한 관련성 신호 | E8, R2 |
| N이 커지면 | Held-Karp는 O(N^2 2^N). N = 10까지 7ms. 그 이상은 NN + 2-opt | T2 |
