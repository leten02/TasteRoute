# TasteRoute 대시보드

이슈 #50 · 코드 `app/dashboard.py`, `app/route_view.html`, `.streamlit/config.toml`

조건을 바꾸면 추천 장소와 **실제 길을 따라가는 도보 경로**가 바로 바뀌는 지도 중심 앱이다. 실험 결과와 데이터 분석도 같은 화면에서 본다. 발표 라이브 데모용으로 만들었다.

## 실행

```bash
pip install -e ".[app]"                 # streamlit, osmnx
python -m tasteroute.roads              # (선택, 한 번만) 도심 보행 도로망 미리 받기, 약 2분
python -m tasteroute.item_extras        # (선택) 영업시간·가게 속성 → 영업시간 필터, 다양성 유사도
python experiments/bpr.py               # (선택) BPR 모델 → 순위 방식에 "BPR 순위 학습" 추가
streamlit run app/dashboard.py          # http://localhost:8501
```

- `data/processed/`가 있어야 한다 (전처리: `python data_analysis_preprocessing/preprocess.py`).
- 실험 결과 탭은 `results/*.json`을 읽는다. 없으면 `python experiments/run_all.py`를 먼저 돌린다.
- 처음 열 때 데이터 로드와 CBF 학습에 약 20초 걸리고, 그 뒤로는 캐시된다.
- **로컬 전용이다.** Yelp 약관상 데이터를 재배포할 수 없어서 `localhost`에만 열리게 설정했다 (`.streamlit/config.toml`의 `server.address`). 공개 서버에 배포하지 않는다.

### 2. 실험 결과

- **요약 타일**: 최저 test RMSE, 거리 재순위화 효과(RQ1), NN + 2-opt 최적해 비율(RQ3), 추천 순서 그대로 돌 때 더 걷는 거리
- **차트 4개**
  1. 별점 예측 모델 비교: 점과 95% 신뢰구간. 차이가 작아서 막대 대신 점을 썼다 (막대는 0에서 시작해야 해서 차이가 안 보인다)
  2. RQ1 거리 감쇠별 정확도와 거리 trade-off
  3. 거리 민감도 학습 vs 고정 규칙
  4. RQ3 추천 순서로 돌 때 더 걷는 비율 분포
- **모델 비교 표**: RMSE, MAE, 신뢰구간, bias 대비 p값, cold-start RMSE. 열마다 가장 좋은 값을 강조한다.

## 고도화 기능 (이슈 #58)

| 기능 | 어떻게 |
| --- | --- |
| **영업시간** | 원본 Yelp `hours`를 분 단위로 읽는다 (자정 넘김, 종일 영업 처리, 자정을 지난 도착은 다음 요일로). 그날 일정 시간(장소 수 × (머무는 시간 + 이동 15분)) 안에 머무는 내내 영업하는 때가 한 번이라도 있는 곳만 후보로 남긴다. 여러 날이면 모든 날에 그런 곳만 (k-means가 날짜를 나중에 정하므로 어느 날에 배정돼도 열려 있게). 방문 순서는 기본으로 영업시간에 맞춘다: 도착 때 닫힌 곳이 가장 적은 순서 중 가장 일찍 끝나는 순서 ([설명](Hours_Route.md)). 도착 시각은 출발 시각 + 도보 시간 + 머무는 시간이고, 열기 전에 도착하면 열 때까지 기다린 뒤 머무는 동안 영업하는지 확인해 카드에 표시한다 (닫는 시각에 딱 맞춰 나오면 영업으로 침). 토글을 끄면 최단 거리 순서를 같은 규칙으로 잰다. 영업시간 정보가 없는 곳은 "정보 없음"으로 두고 제외하지 않는다 |
| **여러 날 코스** | 상위 `날짜 × 하루 장소 수`곳을 고른 뒤, 지도 좌표(km)로 **용량 제한 k-means**(`cluster.balanced_kmeans`, 직접 구현)로 날짜 수만큼 동네를 나눈다. 일반 k-means는 11곳/1곳처럼 치우치게 나눠서, 가까운 (장소, 중심) 쌍부터 자리가 남은 동네에 배정하는 단계를 넣었다. 동네마다 출발지에서 Held-Karp로 경로를 짜고, 가장 추천 순위가 높은 장소가 든 동네를 1일차로 둔다 |
| **다양성 (MMR)** | `(1 − λ)·관련도 − λ·max(이미 고른 곳과의 유사도)`가 가장 큰 곳을 하나씩 고른다 (Carbonell & Goldstein, 1998). 유사도는 카테고리 + 가게 속성 벡터의 cosine. λ = 0이면 점수 순서 그대로 |
| **BPR 순위 학습 + 거리** | 실험(#52)에서 학습한 BPR 모델 점수를 인기도 섞지 않고 그대로 쓰고, 거리 감쇠 τ로 재순위화한다. 새 방문자는 장소 편향(인기도에 해당)만 쓴다 |

## 동작 방식

```
사이드바 선택 ─▶ run_plan (st.cache_data: 같은 조합은 다시 계산 안 함)
                   ├─ 예상 별점: CBF (새 방문자는 μ + b_i)
                   ├─ pipeline.plan_day(visit=학습 모델 | tau=고정 규칙, roads="osm")
                   │     후보 → 순위 → OpenStreetMap 도보 거리 → Held-Karp
                   └─ 반환: 방문 순서, 추천 순서, 구간 거리, 경로 좌표 2개
                 ─▶ route_view.html 에 JSON으로 넣어 iframe으로 그림 (Leaflet)
```

- **예상 별점은 CBF를 쓴다.** Hybrid와 RMSE가 같고(1.051), MF 학습 없이 몇 초 만에 준비된다. 학습된 순위 모델은 Hybrid 예상 별점으로 학습했지만, 두 모델의 예상 별점 척도가 같아서 그대로 쓴다.
- **후보 200곳**: 고정 규칙도 학습 모델과 같이 후보 200곳에서 순위를 매긴다. 카테고리와 출발지를 고르면 도시 전체 인기 상위 50곳 안에는 가까운 곳이 거의 없기 때문이다 (University City 출발 피자 6곳: 50곳일 때 11.0km, 200곳일 때 5.8km). 실험에서도 후보 200곳이 NDCG@10을 0.0340에서 0.0373으로 올렸다.
- **도로망 캐시**: 요청한 범위를 이미 받아 둔 도로망이 덮으면 그것을 쓴다. `python -m tasteroute.roads`로 도심 전체(북 39.978, 남 39.928, 동 −75.128, 서 −75.205)를 한 번 받아 두면 그 안의 모든 코스가 바로 나온다.
- **도로망 서버 장애 대응**: 도로망을 주는 공용 서버(Overpass)가 바쁘거나 연결을 거부하면, 앱은 한 번 25초까지만 시도한다. 실패하면 경고를 띄우고 그 세션 동안 **캐시 전용**으로 바꾼다. 받아 둔 지역은 계속 도보 경로로, 아닌 지역은 기다림 없이 직선 경로로 보여 주고, "도보 경로 다시 시도" 버튼을 둔다. (개발 중 실제로 서버가 연결을 거부했고, 처음 구현에서는 세 번 재시도하느라 4분 넘게 멈췄다.)
- **지도 타일**: OpenStreetMap 기본 타일을 CSS 필터로 채도를 낮춰 경로가 돋보이게 했다. API 키가 필요 없다. CARTO 타일은 이제 API 키가 필요해서 쓰지 않았다. 처음에는 MapLibre(WebGL)를 썼지만, WebGL이 없는 환경(일부 발표용 PC, 헤드리스 브라우저)에서 지도가 비어서 Leaflet으로 바꿨다.

## 알려진 한계

- `st.components.v1.html`은 Streamlit이 사용 중단을 예고한 API다 (설치된 1.66에서는 경고만 나오고 동작한다). 다음 버전에서 사용자 정의 컴포넌트로 옮겨야 할 수 있다.
- 영업시간은 Yelp 데이터 기준(2022년 1월)이라 현재와 다를 수 있다.
- 방문 순서는 영업시간에 맞추지만(닫힘 최소, 그다음 가장 이른 종료), 후보 필터는 장소를 하나씩 확인한다. 그래서 고른 장소들이 한꺼번에 맞는 순서가 없으면 "도착 시 닫힘"이 남을 수 있다 (임의 일정 400개 중 60개). 숨기지 않고 카드에 표시한다. 자세한 내용은 [영업시간을 고려한 방문 순서의 한계](Hours_Route.md#한계).

## 검증

- 헤드리스 브라우저로 세 탭을 열어 화면을 확인했다: 지도 타일, 경로, 카드 클릭 시 지도 이동과 팝업, 같은 건물 핀 비켜 놓기, 추천 순서 경로 켜기, 차트, 표.
  - 이 과정에서 고친 것: WebGL 없는 환경에서 지도가 비는 문제(MapLibre → Leaflet), CARTO 타일이 "API KEY REQUIRED" 이미지를 주는 문제(→ OSM 타일), 모델 비교 막대가 축 이름을 덮는 문제(→ 점 + 신뢰구간), RQ1 범례가 데이터를 가리는 문제, 로고 윗부분 잘림
- 고도화 기능(#58)은 `AppTest`로 순위 방식 3종 × 1~3일 × 다양성 × 영업시간 켜기·끄기 × 도보·직선 조합 5가지를 돌려 예외가 없음을 확인했다. 2일 코스 화면에서 처음엔 k-means가 11곳/1곳으로 나눠 용량 제한 k-means로 고쳤다 (6곳/6곳).
